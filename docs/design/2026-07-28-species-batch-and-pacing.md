# 新種5匹の一括追加と誕生ペーシング（必要餌数の漸増）

- 日付: 2026-07-28
- 状態: オーナー承認済み
- 目的: 図鑑を3種→8種に拡張し、発見数に応じて必要餌数を段階的に増やすことで後半の寿命を伸ばす

## 背景

図鑑が3種しかない状態では全種発見が早すぎ、コレクション体験が短命に終わる。種を増やすにあたって、後半も新鮮な緊張感を保てるようペーシングを同時に設計した。必要餌数の固定値（`SATIETY_MAX = 5`）を廃止し、発見数に応じて漸増する純粋関数に置き換えることで、セーブスキーマを変えずにスケール可能な仕組みにする。

## 決定: 追加5種（テーマ「食べもの × 海の生きもの」）

全て S 階級（16×16・2フレームアニメ）。5色パレット規律（H/L/S/M/E + 目 O）に従い、種ごとに独立したパレットを持つ。

| 種ID | 名前 | コンセプト | アニメーション |
|---|---|---|---|
| `shoyuDai` | しょうゆだい | 弁当の魚型醤油容器。半透明白ボディ・醤油色・赤キャップ | キャップの光沢（オーナー発案） |
| `sodaClownfish` | ソーダクマノミ | オレンジソーダ色 × 白縞のクマノミ型 | 尾びれ |
| `colaClownfish` | コーラクマノミ | コーラ色 × クリーム縞のクマノミ型 | 尾びれ |
| `konpeitoStarfish` | こんぺいとうヒトデ | パステルピンクの星形 | ツノのきらめき |
| `macaronPuffer` | マカロンフグ | ピスタチオ色のまんまるフグ | ぷくっと膨張 |

クマノミ2種は同じ形状テンプレート × 異なるフレーバーパレットで「量産式」を踏襲する。

### 見送り

- **チョコミントクラゲ** — クラゲ枠は既存のストロベリークラゲが担当しているため、次回候補へ持ち越す

### 泳ぎの個性（目安。実装計画で具体値確定）

| 種 | 特徴 |
|---|---|
| ソーダクマノミ / コーラクマノミ | やや速め |
| こんぺいとうヒトデ | 最遅・bob 大きめ |
| マカロンフグ | 中速 |
| しょうゆだい | 標準 |

## 決定: ペーシング（誕生コストの漸増）

### 方式: satietyMax 漸増式

```
satietyMax(zukan) = 5 + floor(min(発見数, 全種数-1) / 2)
```

発見数を `全種数-1` でキャップするため、全種発見後も値は増えない。

8種での必要餌数の変化:

| 発見数 | 必要餌数 |
|---|---|
| 0〜1 種 | 5 匹 |
| 2〜3 種 | 6 匹 |
| 4〜5 種 | 7 匹 |
| 6〜7 種 | 8 匹 |
| 全種発見後 | 8 匹（変化なし） |

### 実装箇所

- **`src/systems/satiety-max.ts`**: `satietyMax(zukan: Zukan): number` を新設。純粋関数。`SATIETY_MAX = 5` 定数の直接参照を廃止し、この関数に集約する
- **`src/ui/hud.ts`（または描画層）**: 満腹ゲージの分母を `/5` 固定から `satietyMax(zukan)` の動的表示に修正する

### セーブスキーマ

変更なし（version 1 のまま）。発見数は `zukan` から毎回導出できるため「次の必要数」を保存する必要はない。繰り越し仕様（`satiety -= satietyMax(zukan)`）もそのまま機能する。

### 不採用案と理由

- **必要餌数に ±ゆらぎを加える** — 「次の必要数」をセーブに持たせる必要があり、スキーマバージョンアップが発生する。効果に比べてコストが高いため見送り（必要になれば v2 化と同時に検討）
- **種別ごとに誕生コストを変える** — 珍しい種を「高コスト」にする意図はあるが、バランス調整が複雑になるため今回は見送り

## 実装の進め方

1. **ペーシング先行**（小さく独立。既存コードへの変更が最小）: `satietyMax` 関数の新設 → `SATIETY_MAX` 参照箇所の置き換え → HUD の動的表示 → ユニットテスト
2. **種追加**（データ一括 + スプライト5ファイル）: SpeciesId 型拡張 → 各 Record への追加 → スプライト PNG/データ 5種 → 泳ぎパラメータ → 動作確認

種追加は `Record<SpeciesId, ...>` の網羅性チェックにより漏れが構造的に防がれる。

## 検証

- `satietyMax` はユニットテストで境界値（発見数 0・1・2・7・8）を全カバーする
- 新 `SpeciesId` の追加は既存の Record 型が網羅チェックになっているため、追加漏れはビルド時に型エラーで検出される
- 各種のスプライトと泳ぎはブラウザ（Chrome）でオーナーが目視確認し、気に入らない種はリテイクする
