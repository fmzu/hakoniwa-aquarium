# 誕生のランダム化（固定テーブル廃止）

- 日付: 2026-07-27
- 状態: オーナー承認済み
- 目的: 誕生順を固定テーブルから「未発見種のランダム抽選（重複なし）」に変更し、図鑑コンプ体験を維持しつつ順番のサプライズを加える

## 背景

固定テーブル（`src/data/birth-table.ts`）は「最後の1種だけが出ない」問題を防ぐために導入した。しかし未発見からしか引かない構造を採用すれば同じ問題は構造的に解消され、順番の予測不可能性も加わる。2026-07-11 オーナーが方向性を決定し、2026-07-27 設計を承認した。

## 決定した方式（案A: 状態レス抽選）

誕生の瞬間に `zukan` から未発見種を導出し、その中から一様抽選する。未発見が空（全種発見済み）なら全種から抽選する。

- **セーブスキーマ変更なし**（version 1 のまま）。未発見リストは図鑑から毎回導出できるため状態を持たない
- **乱数は引数注入**（既存 `random` パラメータの慣習に沿う）

### 不採用案と理由

- **案B: シャッフル順列をセーブに保存** — スキーマ変更・種追加時の挿入ロジックが必要。事前確定順を活用する機能（予告演出等）がまだ存在しない（YAGNI）
- **案C: 重み付き抽選** — レア度データが存在しない。時期尚早

## 変更箇所

- **`src/systems/next-birth-species.ts`**: シグネチャを `nextBirthSpecies(zukan, random)` に変更。未発見種配列を作り `random` で1種選ぶ。純粋関数のまま
- **`src/systems/step-world.ts`**: 誕生処理で `zukan` と `random` を渡す（`stepWorld` が `zukan` を保持していなければ引数追加。`main.ts` 側は `zukan` 保持済み）
- **削除**: `src/data/birth-table.ts` と `src/data/birth-table.test.ts`
- **全種リスト**: 既存の `Record<SpeciesId, ...>`（`species-names` 等）から導出するか、小さな定数ファイルを1つ追加する（一関数一ファイル遵守）

## 全種発見後の挙動

全種発見済みのとき、発見済みの全種からランダム抽選する。誕生イベント自体は変わらず発生し続ける（図鑑の誕生数カウンターが増える）。

## エッジケース

- **同tick二重誕生の重複なし**: 繰り越し制により同tickに複数誕生は構造的に不可能。抽選→即図鑑登録の順で処理するため重複は起きない
- **新種追加の互換性**: 既存プレイヤーは自動的に新種が未発見プールに入る。マイグレーション不要

## スコープ外（オーナー確認済み）

- **ペーシング**（必要餌数ゆらぎ・種別コスト・後半逐増）— 種が増えたタイミングで別途設計
- **色違いプール解禁**（全種発見後に同形状×別パレットの変種を追加）— 後日設計

## テスト（next-birth-species.test.ts 書き直し）

1. 未発見が残っているとき、選ばれる種は必ず未発見のいずれかである
2. 全種発見済みのとき、全種のいずれかが選ばれる
3. 乱数値に応じた選択の決定性（同じ `random` → 同じ種）
4. 未発見が1種のときその種が確実に選ばれる
